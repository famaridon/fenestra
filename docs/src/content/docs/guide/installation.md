Fenestra is not distributed on the App Store: an app cannot be sandboxed while driving windows through the Accessibility API. You build it from source instead.

:::note
The app's interface is currently in French only. An English version is planned.
:::

## Requirements

- macOS 26 or later
- A Mac with Apple silicon
- Xcode (with an account that provides an **Apple Development** certificate)
- [Homebrew](https://brew.sh) to install XcodeGen

## Build from source

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`; the `.xcodeproj` is not under version control.

```sh
brew install xcodegen
xcodegen generate
open Fenestra.xcodeproj
```

In Xcode, select the **Fenestra** scheme and click **Run** (⌘R).

## First launch and Accessibility permission

Fenestra lives in the **menu bar**: it has no Dock icon. On first launch, a welcome window walks you through granting the Accessibility permission and shows its status live.

1. Open **System Settings > Privacy & Security > Accessibility**.
2. Turn on the switch next to **Fenestra**.
3. Go back to the welcome window: the status changes to granted and Fenestra starts its monitors.

:::note
Without this permission, Fenestra can neither move nor resize other apps' windows.
:::

## Why an Apple Development signature?

macOS ties the Accessibility permission to the app's signing identity. An "ad hoc" signed build gets a new identity on every build, and the permission is lost. With a stable **Apple Development** certificate, macOS recognizes the app from one build to the next and **keeps the permission**.

## Avoid double snapping

macOS 26 has its own window tiling. To keep both systems from reacting at the same time, turn off native drag tiling:

**System Settings > Desktop & Dock > Windows**, then turn off tiling windows by dragging them to the screen edges.

Fenestra works alongside native tiling, but turning it off is recommended.

## Launch at login

In Fenestra's settings (**General** tab), turn on **Launch at login**. Fenestra uses `SMAppService` for this.
