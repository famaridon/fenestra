title: Installation

Fenestra is not distributed on the App Store: an app cannot be sandboxed while driving windows through the Accessibility API. Download a ready-made build from GitHub, or build it from source.

## Requirements

- macOS 26 or later
- A Mac with Apple silicon

## Download a release

1. [Download Fenestra](https://github.com/famaridon/fenestra/releases/latest/download/Fenestra.zip) (latest version, `Fenestra.zip`), unzip it and move `Fenestra.app` to `/Applications`.
2. Builds are **not signed or notarized yet**, so macOS refuses to open the app on first launch. Remove the quarantine flag in a terminal:

   ```sh
   xattr -dr com.apple.quarantine /Applications/Fenestra.app
   ```

3. Launch Fenestra, then grant the Accessibility permission (see below).

Previous versions and their changes are listed on the [releases page](https://github.com/famaridon/fenestra/releases).

:::caution[Updates]
An unsigned build changes identity with each version, so macOS forgets the Accessibility permission. After an update, remove the old Fenestra entry from the Accessibility list and grant the permission again.
:::

## Build from source

You also need Xcode (with an account that provides an **Apple Development** certificate) and [Homebrew](https://brew.sh) to install XcodeGen.

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`; the `.xcodeproj` is not under version control.

```sh
brew install xcodegen
xcodegen generate
open Fenestra.xcodeproj
```

In Xcode, select the **Fenestra** scheme and click **Run** (⌘R).

## First launch and Accessibility permission

Fenestra lives in the **menu bar**: it has no Dock icon. On first launch, a welcome window walks you through granting the Accessibility permission and shows its status live.

1. Open **System Settings > Privacy & Security > Accessibility**.
2. Turn on the switch next to **Fenestra**.
3. Go back to the welcome window: the status changes to granted and Fenestra starts its monitors.

:::note
Without this permission, Fenestra can neither move nor resize other apps' windows.
:::

A second permission, **Screen & System Audio Recording**, is optional: it is only needed for [window thumbnails in Snap Assist](/fenestra/guide/snap-assist/#window-thumbnails), and Fenestra only asks for it when you turn that option on.

## Why an Apple Development signature?

macOS ties the Accessibility permission to the app's signing identity. An "ad hoc" signed build gets a new identity on every build, and the permission is lost. With a stable **Apple Development** certificate, macOS recognizes the app from one build to the next and **keeps the permission**.

## Avoid double snapping

macOS 26 has its own window tiling. To keep both systems from reacting at the same time, turn off native drag tiling:

**System Settings > Desktop & Dock > Windows**, then turn off tiling windows by dragging them to the screen edges.

Fenestra works alongside native tiling, but turning it off is recommended.

## Launch at login

In Fenestra's settings (**General** tab), turn on **Launch at login**. Fenestra uses `SMAppService` for this.
